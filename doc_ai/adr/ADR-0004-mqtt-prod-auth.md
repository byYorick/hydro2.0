# ADR-0004. Защита MQTT в prod

**Версия:** 0.1
**Дата:** 2026-11-09
**Статус:** `proposed`
**Метки:** текущий prod-контур — **live**; учётка на узел, отдельный ключ обёртки и выключенный host-порт 1883 — **planned**. Dev-compose этот ADR не ужесточает.

Compatible-With: Protocol 2.0, Backend >=3.0, Python >=3.0, Database >=3.0, Frontend >=3.0.
Топики и payload команд не меняются. Меняются учётные данные, ACL, обёртка
`node_secret` и транспорт prod (TLS).

## Контекст

Сверено с `main` @ `ba461dce`. Обзор по этому пункту совпадает с кодом; ниже уточнения, без которых план миграции будет дырявым.

### Общий логин и ACL по client id (**live**)

- Prod требует `MQTT_ESP32_NODE_PASS`. Комментарий `.env.prod.example:48–49`: это пароль пользователя `esp32_node`.
- ACL (`backend/services/mqtt-bridge/acl` и `acl.example`, блок `user esp32_node` со строки 35) пускает все ноды одним логином.
- Строки `pattern` в том же файле (с строки 53) в Mosquitto применяются ко всем пользователям, подставляя `%c` (client id). Они не ограничены пользователем `esp32_node`. Комментарий файла верен: прошивка ставит client id = `node_uid` (`mqtt_manager.c:313–318`), а сервисные client id не должны с ним совпадать.
- Следствие: кто знает общий пароль и подставляет чужой client id, проходит pattern на топики этой ноды. ACL проверяет client id, не «этот логин — эта нода».

Прошивка уже умеет отдельное имя: NodeConfig `mqtt.username` / `mqtt.password` читаются в `config_storage.c:988`, в клиент попадают из `mqtt_manager.c:365–368`.

### Один ключ обёртки (**live**)

`node_secret` в MQTT не кладётся открытым текстом. history-logger оборачивает его в `node_secret_enc` (AES-256-GCM, AAD = `node_uid`): `backend/services/history-logger/commands/node_secret_wire.py`.

Ключ — SHA-256 от метки `hydro.node_secret.wrap.v1` и **одной** passphrase: `NODE_SECRET_WRAP_PASSPHRASE`, иначе `MQTT_ESP32_NODE_PASS` (`node_secret_wire.py:71–76`). В dev оба по умолчанию `esp32_pass` (`docker-compose.dev.yml:304–305`). В prod пример оба пустые и прямо сказано, что wrap — тот же пароль, что `mqtt.password` узла (`.env.prod.example:50–52`). AAD различает шифртексты, ключ — нет. Пароль `esp32_node` расшифровывает секрет любой ноды.

Прошивка снимает обёртку тем же KDF и паролем из объекта `mqtt` применяемого конфига (`config_storage.c`, `derive_node_secret_wrap_key` и `config_mqtt_password`).

### Plaintext 1883 наружу (**live**)

- `backend/docker-compose.prod.yml:24` — `MQTT_PLAINTEXT_ENABLED` по умолчанию `1`.
- Порты: `${MQTT_BIND_ADDR:-0.0.0.0}:1883:1883` и `${MQTT_TLS_BIND_ADDR:-0.0.0.0}:8883:8883` (строки 26–27).
- `mosquitto.prod.conf` объявляет `listener 1883` и `allow_anonymous false`. Анонимного входа нет; открыт парольный plaintext на всех интерфейсах.
- `mosquitto-entrypoint.sh:44–46` удаляет строку `listener 1883`, только если флаг равен `0`. Healthcheck compose всё равно делает `nc -z localhost 1883` (`docker-compose.prod.yml:37`) и при выключенном plaintext станет красным.
- TLS 8883 добавляется, если смонтированы `server.crt` и `server.key`. Entrypoint ставит `require_certificate false` и `tls_version tlsv1.2` (`mosquitto-entrypoint.sh:68–75`). Это проверка сервера клиентом, не клиентские сертификаты.
- Прошивка: `use_tls` переключает URI на `mqtts://` (`mqtt_manager.c:305`) и подставляет CA из `ca.pem`, если файл был на машине сборки (`mqtt_manager/CMakeLists.txt:8–12`). Файла в git нет. Без него TLS-сборка не проверяет брокера. OTA, которым можно было бы доставить CA без перепрошивки, в runtime нет (**planned**, `IMPLEMENTATION_STATUS.md`).

Dev (`docker-compose.dev.yml`, порт 1883, пользователь `esp32_node`) этим ADR не переводится на TLS.

## Решение

### 1. Учётка на узел, не клиентский сертификат

Сравнение для сезонной теплицы в Крыму, десятки нод на модуль, без отдельного бюджета на PKI:

| | Логин и пароль на ноду + TLS сервера | Клиентский сертификат (mTLS) |
|---|---|---|
| Что уже есть | `mqtt.username` / `password` в NodeConfig и NVS; `use_tls` в прошивке | `require_certificate false`; своего выпуска сертификатов нет |
| ESP32 | одна TLS-сессия, CA в прошивке, пароль в NVS. RAM уже заложен под MQTT task | плюс клиентский ключ и цепочка в handshake. На ESP32 (не S3) запас RAM рядом с Wi-Fi маленький, портал должен уметь залить PEM, ротация — перепрошивка, пока нет OTA |
| Брокер | `password_file` и ACL, которые уже используются | CA, CRL или список, операторская процедура отзыва |
| Что даёт | чужой пароль больше не годится на все ноды; пароль по проводу не виден, если только 8883 | украденный `passwords.txt` не подписывает команды; ключ из flash ESP32 всё равно можно вычитать, secure element не заложен |
| Цена | генерация пароля в Laravel и строка ACL на ноду | тот же TLS плюс PKI, который некому сопровождать на паузе декабрь–февраль |

Решение: **учётка на ноду и TLS только сервера**. `require_certificate` остаётся `false`. mTLS не блокер модуля 400 м². Вернуться к нему можно отдельным ADR для узла раствора, если появится secure element или OTA. Смешивать оба способа в одном выкате не будем.

Имя пользователя = `nodes.uid`. Пароль — случайный, не равный паролю другой ноды и не равный `MQTT_ESP32_NODE_PASS`. Client id прошивка по-прежнему ставит в `node_uid`. ACL на это не полагается как на единственную проверку (§2).

### 2. ACL по логину

Глобальные `pattern write … %c` для нод убираются. Иначе пароль ноды A и client id ноды B снова проходят, потому что `pattern` общий на всех пользователей.

На каждую ноду генератор пишет блок:

```
user nd-ph-1
topic read hydro/+/+/nd-ph-1/config
topic read hydro/+/+/nd-ph-1/+/command
topic write hydro/+/+/nd-ph-1/+/telemetry
topic write hydro/+/+/nd-ph-1/status
topic write hydro/+/+/nd-ph-1/heartbeat
topic write hydro/+/+/nd-ph-1/lwt
topic write hydro/+/+/nd-ph-1/diagnostics
topic write hydro/+/+/nd-ph-1/error
topic write hydro/+/+/nd-ph-1/config_report
topic write hydro/+/+/nd-ph-1/node_hello
topic write hydro/+/+/nd-ph-1/+/command_response
topic write hydro/+/+/nd-ph-1/+/event
```

Плюс общие `hydro/node_hello` и `hydro/time/request` / `response`, как сейчас у `esp32_node`, и pre-bind `gh-temp` — только пока нода не привязана; после bind строки `gh-temp` из её блока снимаются.

Пишет файл не руками: Laravel хранит учётку, Hydro2 Автоматика собирает `passwords` и `acl` и перезагружает брокер (`SIGHUP` Mosquitto, без рестарта контейнера, если конфиг это позволяет; иначе короткий рестарт только процесса брокера, порты те же). Порог «перейти на dynamic security plugin» — сотни нод и боль от reload. Для N модулей по ~4 зоны файл достаточен, plugin не вводим.

Сервисные пользователи (`history_logger`, `mqtt_bridge`) остаются. `history_logger` по-прежнему единственный, кто пишет `command` и `config`.

### 3. Ключ обёртки на ноду

Отдельный секрет от MQTT-пароля. Иначе файл `passwords.txt` остаётся оракулом для всех `node_secret`.

- На ноду Laravel генерирует `secret_wrap_key` (32 байта) и хранит его и MQTT-пароль через шифрование Laravel (`APP_KEY`), не в открытом JSON `nodes.config` и не в логах.
- `node_secret_enc` собирает Laravel. history-logger перестаёт оборачивать глобальной passphrase и не подставляет `MQTT_ESP32_NODE_PASS`. Публикация plaintext `node_secret` по-прежнему запрещена: нет ключа — поле не уходит в MQTT, в лог пишется uid без секрета (как ветка `withheld` в `prepare_node_config_for_mqtt`).
- Прошивка хранит wrap key в NVS. Кладёт его setup portal по локальной точке доступа, не топик MQTT. Снятие `node_secret_enc` идёт этим ключом, не `mqtt.password`. Метка KDF остаётся `hydro.node_secret.wrap.v1`, AAD остаётся `node_uid`.
- Пока на ноде старая прошивка, окно миграции (§5) один раз оборачивает секрет её текущим MQTT-паролем, и этот пароль уже индивидуальный. Глобальный `esp32_pass` / `MQTT_ESP32_NODE_PASS` для новых обёрток не используется. После прошивки с NVS-ключом парольный KDF отключается.

Компрометация одной ноды раскрывает её HMAC-секрет и её MQTT-пароль, не секреты соседних.

### 4. Plaintext 1883 в prod выключен

- В `docker-compose.prod.yml` дефолт `MQTT_PLAINTEXT_ENABLED` становится `0`.
- Проброс `1883` на хост из prod-файла убирается. Дефолт `MQTT_BIND_ADDR=0.0.0.0` для этого порта не возвращать.
- Слушатель 8883 — рабочий. Внутренние сервисы (history-logger и те, кто ещё ходит в брокер) подключаются к `mqtt:8883` с `ca.crt` (`MQTT_TLS=1`, заготовка уже в `.env.prod.example`). Отдельный «тихий» 1883 внутри docker-сети не оставляем: один слушатель проще сверять и не забыть в healthcheck.
- Healthcheck смотрит 8883, не 1883.
- Анонимный доступ не включается. `allow_anonymous false` сохраняется.
- CA площадки зашивается в прошивку через уже существующий `ca.pem` на сборке. Поворот CA до появления OTA — перепрошивка. В ADR не обещать доставку CA порталом: портал в этом решении везёт логин, пароль и wrap key.

Dev-стек не трогать: `1883` и общий `esp32_node` остаются локальной разработкой.

### 5. Миграция действующих нод без простоя

Оба слушателя живут вместе, пока последняя нода не уедет. Откат — включить старое обратно, а не «перерезать всем».

1. Выпустить серверный сертификат (`generate_mqtt_certs.sh`), поднять 8883 рядом с 1883. Старые ноды остаются на 1883 и `esp32_node`.
2. Сгенерировать каждой ноде пароль и wrap key, не выключая `esp32_node`. Собрать ACL, где есть и старый пользователь, и блоки `user <uid>`.
3. Перевести ноды по одной. Предпочтительно setup portal (локальный AP): `username`, новый пароль, `use_tls=true`, порт 8883, wrap key в NVS. Нода, которая ещё не умеет отдельный wrap key, на этом шаге получает индивидуальный MQTT-пароль, и текущая обёртка `node_secret_enc` считается от него, не от общего.
4. Признак готовности ноды — heartbeat и `config_report` уже на 8883 под своим логином. Список непереведённых виден по последнему подключению пользователя `esp32_node` (лог брокера).
5. Когда таких не осталось: `MQTT_PLAINTEXT_ENABLED=0`, убрать проброс 1883, отключить пароль `esp32_node` (строку пользователя не удалять до конца окна отката — пароль заменить на недействительный и сохранить прежний в сейфе оператора, не в git).
6. Прошивка с NVS wrap key выкатывается на ноду в удобное окно. До неё индивидуальный пароль уже ограничивает обёртку одной нодой.

Окно, в котором 1883 ещё открыт, держать коротким и не на `0.0.0.0`, если хост позволяет привязать временный слушатель к LAN теплицы. Дефолт «открыть всему миру на время миграции» не использовать: текущий `MQTT_BIND_ADDR=0.0.0.0` как раз это и есть, его меняют в шаге 1 на адрес LAN, не дожидаясь шага 5.

### 6. Откат

8883 не выключать.

1. Вернуть прежний пароль `esp32_node` из сейфа, `MQTT_PLAINTEXT_ENABLED=1`, слушатель 1883 только на адрес LAN.
2. Ноды, уже переведённые на 8883 и личный логин, продолжают работать.
3. Нода, которая не смогла подключиться по TLS, поднимается со старыми NVS (общий логин, 1883), если портал не стёр старый конфиг до успешного коннекта. Поэтому портал записывает новые значения только после того, как нода установила пробную сессию, либо хранит предыдущий `mqtt`-блок и умеет вернуться к нему за одну перезагрузку. Это требование к прошивке портала, не к брокеру.
4. Закрыть 1883 снова, когда причина отката снята. Общий пароль не оставлять «на всякий случай» дольше окна.

## Альтернативы

- Только закрыть 1883, оставив `esp32_node`. Отклонено: пароль один, ACL по client id, wrap тем же паролем. TLS прячет пароль в пути, но угон одной ноды или `passwords.txt` по-прежнему даёт все ноды.
- mTLS сразу. Отклонено для первой очереди: нет OTA и PKI, RAM и операционная цена для сезонной площадки выше, чем персональные пароли. Дверь для отдельного ADR оставлена.
- Dynamic security plugin Mosquitto сразу. Отклонено: файл ACL на ожидаемое число нод перезагружается проще, чем новый контур.
- Оставить 1883 внутри docker-сети навсегда. Отклонено: healthcheck и люди продолжат считать plaintext рабочим портом, а флаг снова уедет на `0.0.0.0`.
- Менять dev так же, как prod. Отклонено: стенд и тесты (`tools/ci/test_mqtt_runtime.py`, node-sim) ходят на 1883. Prod-дефолт и dev-дефолт различаются явно.

## Последствия

- Пока ADR `proposed`, prod по умолчанию слушает 1883 на `0.0.0.0` (**live**). В теплицу этот стек так не ставить.
- После принятия угон одной ноды не даёт MQTT-пароля и HMAC-секрета соседней. Угон `passwords.txt` даёт MQTT-вход на все перечисленные ноды, но не wrap key и не `node_secret`, если шаг с отдельным ключом уже включён.
- CA в прошивке: смена CA = перепрошивка, пока OTA **planned**. Сертификат делать с запасом по сроку на сезон, SAN — DNS и LAN IP брокера.
- `history-logger` остаётся единственным publisher команд. Его пароль тоже не общий с нодами; ротация сервисных паролей не входит в этот ADR, но хранить их в git по-прежнему нельзя.
- Реализация обновляет `SECURITY_ARCHITECTURE.md`, `NODE_CONFIG_SPEC.md` (чем снимается обёртка) и комментарии compose. Этот ADR их не заменяет.
- Android-клиент к брокеру нод этим решением не подключается (у приложения нет MQTT-клиента в рабочем контуре).

## Задачи

### Hydro2 Бэк

Laravel, учётные данные и provisioning:

- колонки (через миграцию, вместе с Hydro2 БД): MQTT-пароль и `secret_wrap_key` в шифровании `APP_KEY`, не в `nodes.config`;
- выпуск и ротация учётки при регистрации ноды и из карточки узла; пароль показывается один раз;
- сборка `node_secret_enc` перед отдачей конфига в history-logger; в лог и в Inertia секрет не попадает;
- контракт setup portal: `username`, пароль, порт 8883, `use_tls`, wrap key. Старый `mqtt`-блок не затирать до успешной проверки сессии;
- список нод, которые ещё на `esp32_node`, для шага миграции.

### Hydro2 Автоматика

mqtt-bridge, history-logger, брокер, compose, TLS:

- генерация `passwords` и ACL блоком на uid, снятие глобальных `pattern write` для нод, reload брокера;
- `prepare_node_config_for_mqtt` не оборачивает глобальной passphrase и не читает `MQTT_ESP32_NODE_PASS` как ключ; plaintext `node_secret` не публикует;
- `docker-compose.prod.yml`: дефолт plaintext `0`, нет проброса 1883, сервисы на 8883, healthcheck на 8883;
- entrypoint: при флаге отката слушатель 1883 не биндится на `0.0.0.0`; `require_certificate false` не переключать на true в этом изменении;
- тест: нода под паролем A не публикует в топик ноды B; `esp32_node` после отключения пароля не подключается.

### Прошивка

Отдельным изменением, не внутри репозитория бэкенда:

- подключение личным `username` и `mqtts://` с зашитым CA (`ca.pem` на сборке);
- wrap key в NVS из портала; KDF им, а не паролем MQTT, после окна миграции;
- откат на предыдущий `mqtt`-блок, если новая сессия не установилась;
- не логировать пароль, wrap key и `node_secret`.

### Hydro2 Фронт

Карточка узла: статус «учётка выдана / ещё общий логин», кнопка ротации без показа хранимого пароля. В мастер теплицы не выводить `MQTT_ESP32_NODE_PASS`.

### Hydro2 БД

Миграция колонок секретов (шифротекст) и отсутствие этих полей в дампах, которые попадают в фикстуры тестов. Сиды не содержат боевых паролей.

## Критерии приёмки

1. В prod-compose по умолчанию нет проброса 1883, healthcheck брокера зелёный по 8883, `MQTT_PLAINTEXT_ENABLED` не равен `1`, пока оператор явно не включил откат.
2. Две ноды с разными uid не аутентифицируются паролем друг друга. Публикация в топик чужого uid с верным своим паролем и подменённым client id получает отказ ACL. Тест это делает против Mosquitto, не моком файла.
3. Файл `acl` после генератора не содержит `pattern write hydro/+/+/%c`.
4. При выключенной глобальной passphrase history-logger не кладёт в payload ни `node_secret`, ни `node_secret_enc`, собранный общим ключом. `node_secret_enc`, собранный ключом ноды, расшифровывается только им (тест KDF на двух ключах).
5. Нода со старым конфигом (`esp32_node`, 1883) остаётся на связи, пока шаг 5 миграции не выполнен. После шага 5 новая нода на 8883 не отваливается.
6. Откат по §6 возвращает 1883 на адрес LAN и прежний пароль `esp32_node`, не стирая личные учётки. Нода, не сумевшая открыть TLS, после перезагрузки снова на старом блоке.
7. В логах laravel, history-logger и прошивки нет пароля, wrap key и `node_secret` (проверка фикстурой, которая кладёт известный маркер и смотрит вывод теста).
