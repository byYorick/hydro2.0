# ADR-0003. `failsafe_state` на канал

**Версия:** 0.1
**Дата:** 2026-11-09
**Статус:** `proposed`
**Метки:** текущее обесточивание — **live**; политика на канал — **planned**. Не контракт NodeConfig, пока статус не `accepted`.

Compatible-With: Protocol 2.0, Backend >=3.0, Python >=3.0, Database >=3.0, Frontend >=3.0.
Поле войдёт в NodeConfig (формат версии 3, новое необязательное поле на канале).
Пока прошивка его не понимает, отсутствие поля обязано совпадать с сегодняшним
«все актуаторы обесточить». Это не ломает уже прошитые ноды.

## Контекст

Сверено с `main` @ `ba461dce`.

Потеря MQTT запускает один таймер на ноду. Поле `link_loss_timeout_sec` (верхний уровень или `fail_safe_guards`) читается в `firmware/nodes/common/components/node_framework/node_link_loss_failsafe.c`. Если значения нет или оно не больше нуля, подставляется 30 с (`NODE_LINK_LOSS_TIMEOUT_SEC_DEFAULT`, строки 28–29 и 76–79). Комментарий в коде: ноль раньше выключал таймер, теперь это не так.

Расхождение со спецификацией (**live**, код важнее): `NODE_CONFIG_SPEC.md` §2.2 пишет, что `0` отключает таймер. Прошивка трактует `0` и пропуск поля одинаково — 30 с. При реализации этого ADR спецификацию выровнять по коду: выключить таймер на ноде с актуаторами нельзя.

По срабатыванию таймер вызывает `node_state_manager_invoke_actuator_failsafe` (`node_link_loss_failsafe.c:130` → `node_state_manager.c:430`). Колбэк один на ноду и гасит все актуаторы:

| Нода | Что делает safe mode | Файл |
|---|---|---|
| `pump_node`, `ph_node`, `ec_node` | `pump_driver_force_deenergize()` — все каналы насоса, GPIO в 0 или реле в `RELAY_STATE_OPEN` | `pump_driver.c:706`, колбэки `*_framework_integration.c` |
| `storage_irrigation_node` | `pump_driver_emergency_stop()` и все актуаторные каналы в `false` | `storage_irrigation_fw_integration.c:41` |
| `relay_node` | `relay_driver_emergency_stop_all_safe()` | `relay_node_framework_integration.c:769` |
| `climate_node` | каждый актуатор `RELAY` / `VALVE` / `FAN` / `HEATER` / `LED` в `RELAY_STATE_OPEN`, PWM duty 0 | `climate_node_framework_integration.c:704–747` |

Обзор («гасит все насосы и реле, включая аэрацию, циркуляцию и вентиляцию») кодом подтверждается. Отдельного исключения для FAN нет: вентилятор в том же цикле, что клапан. Поля `failsafe_state` в прошивке и в Laravel нет.

Рядом живёт другой смысл слова fail-safe, его не переиспользовать. `safe_limits.fail_safe_mode` и `relay_type` — это `NC` / `NO`, электрика контакта (`NODE_CONFIG_SPEC.md` §3.4.2, `ph_node_channel_map.c`). Обесточенный NC-контакт остаётся физически замкнут. Это не политика «держать аэрацию».

E-STOP — отдельный путь: `actuator_failsafe` и `storage_irrigation_fw_fail_safe.c` обесточивают выходы и не восстанавливают снимок после отпускания кнопки. Его этот ADR не ослабляет.

JSON Schema NodeConfig в `backend/services/common/schemas/` нет (там command, telemetry, status, heartbeat, error). PR #32 это уже отмечает.

## Решение

### 1. Поле канала

На объекте канала `ACTUATOR` в NodeConfig:

```json
{
  "name": "air_pump",
  "type": "ACTUATOR",
  "actuator_type": "PUMP",
  "failsafe_state": "on",
  "failsafe_limits": {
    "max_on_sec": 3600,
    "on_sec": 30,
    "off_sec": 90,
    "max_current_ma": 800
  }
}
```

`failsafe_state`: `off` | `on` | `hold` | `cycle`.

| Состояние | Потеря связи после таймера | Перезагрузка после чтения NodeConfig из NVS |
|---|---|---|
| `off` | обесточить | обесточить |
| `on` | вывести в включённое и держать | включить до подключения MQTT, не ждать брокера |
| `hold` | оставить уровень, который был в RAM | обесточить (RAM пуст; это не `on`) |
| `cycle` | локальный таймер ноды, без MQTT | старт с фазы `off` на `off_sec`, затем цикл |

`failsafe_limits` обязателен для `cycle` (`on_sec`, `off_sec`). Для `on` и `hold` лимиты опциональны, кроме правил §3. Чужие ключи и неизвестное состояние — канал в `off`, в `config_report` ошибка поля, остальные каналы применяются.

Имя `fail_safe_mode` не занимать: оно остаётся `NC`/`NO`.

### 2. Кто сильнее

1. E-STOP и safe-state кнопки — обесточить все каналы, игнорируя `failsafe_state`. Аэрация при нажатой кнопке тоже гаснет. Контракт `AE3_IRR_FAILSAFE_AND_ESTOP_CONTRACT.md` не меняется.
2. Потеря связи и загрузка — таблица §1.
3. Команда с сервера после восстановления связи — обычный режим, политика канала её не блокирует, кроме дозатора (§3).

Таймер `link_loss_timeout_sec` остаётся одним на ноду (дефолт 30 с, ноль не отключает). По срабатыванию каждый канал идёт в своё состояние, а не в общий «всё открыто/всё закрыто».

### 3. Жёсткие запреты

Дозатор (команда `dose`, роль канала дозирования, `actuator_type` `PERISTALTIC_PUMP`) принимает только `off`. `on`, `hold` и `cycle` для него отклоняет и Laravel при сборке NodeConfig, и прошивка при применении. Дефолт не «предпочтение», а запрет.

`on` и `cycle` разрешены только ролям из списка: `aeration`, `circulation`, `exhaust_fan`. Неизвестная роль при значении не `off` применяется как `off`.

`hold` запрещён дозатору и клапану полива. После reboot `hold` всегда `off`, даже если роль разрешала удержание на время обрыва.

Автоматически гасить `on` по таймеру «прошло N секунд без MQTT» нельзя: для DWC это кислородное голодание, ради которого поле и вводится. Страховка другая:

- роль из списка допуска;
- для `cycle`: `on_sec` от 1 до 3600, `off_sec` от 1 до 86400, `on_sec` ≤ `max_on_sec` (потолок 3600);
- если на канале есть датчик тока и задан `max_current_ma` — превышение обесточивает канал (короткое). Нет датчика тока — `on` всё равно допустим для роли из списка; риск зафиксирован в последствиях, а не прячется.

Невалидный `cycle` не «лучший effort», а `off`.

### 4. Дефолты, которые пишет Laravel

Прошивка не знает сезон Крыма и не подставляет аэрацию сама. Нет поля — канал `off` (как сегодня). Laravel обязан записать поле до publish, иначе сервер не публикует конфиг роли из списка допуска с пустым `failsafe_state`.

| Роль канала | Дефолт | Когда |
|---|---|---|
| Дозатор pH/EC | `off` | всегда, любое `hydro_system` |
| Насос и клапан полива, drain прилива | `off` | `drip`, `ebb_flow` |
| Циркуляция NFT | `on` | `hydro_system=nft` |
| Аэрация DWC | `on` | `hydro_system=dwc` |
| Вытяжка `exhaust_fan` | `on` | среда `greenhouse` и в профиле теплицы включён режим охлаждения |
| Нагреватель | `off` | всегда в этом ADR; обогрев ночью не становится failsafe |
| Всё остальное | `off` | в том числе пока тип системы `needs_review` |

Режим охлаждения — флаг в существующем greenhouse climate profile, который оператор или сезонное расписание включает на лето. Месяц в прошивку не зашивается. Зимой флаг снят, вытяжка в конфиге снова `off`, и обрыв связи её не включает.

Смена дефолта — новый NodeConfig через history-logger, не команда в обход него.

### 5. Схема и паритет

Файл `backend/services/common/schemas/node_config.schema.json` описывает канал и `failsafe_state` / `failsafe_limits`. Полный NodeConfig в эту схему входит настолько, насколько поля уже есть в `NODE_CONFIG_SPEC.md` §2–3; не описанное в спецификации не объявляется обязательным этим ADR.

Паритет:

- Laravel `NodeConfigService` валидирует тем же набором значений, что схема;
- pytest jsonschema на фикстурах `off` / `on` / `hold` / `cycle` и на дозаторе с `on` (ожидается отказ);
- host-тест прошивки на чистой функции разбора (без ESP-IDF): те же фикстуры, дозатор `on` → отказ, отсутствует поле → `off`.

Три проверки входят в CI. Расхождение — падение, не лог.

## Альтернативы

- Оставить один колбэк «гасить всё» и увеличить таймаут до часов. Отклонено: дозатор и клапан полива тогда остаются под напряжением столько же, сколько аэрация.
- Кодировать политику в `fail_safe_mode` (`NC`/`NO`/`HOLD`). Отклонено: поле уже значит электрику контакта; NC-реле и «держать аэрацию» перепутаются.
- Хранить политику только в AE3 и слать команду «включи компрессор» каждые 30 с. Отклонено: при мёртвом MQTT команда не дойдёт, а включить аэрацию нужно как раз тогда.
- Дать `on` любому каналу, включая дозатор. Отклонено.
- Гасить `on` через `max_on_sec` без связи. Отклонено для аэрации и циркуляции: лимит превращается в отложенный link-loss.

## Последствия

- Пока ADR `proposed`, ноды гасят все актуаторы через 30 с (**live**). DWC и NFT так запускать нельзя.
- После прошивки старый конфиг без поля ведёт себя как сейчас (`off`). Аэрация включится только когда Laravel опубликует `failsafe_state=on`.
- E-STOP по-прежнему гасит всё, в том числе компрессор. Это сознательно: кнопка сильнее агрономии.
- `hold` не переживает reboot. Оператор, который рассчитывал «как было», после питания получит `off` и событие, когда связь вернётся.
- Компрессор без датчика тока может остаться включённым при коротком замыкании, пока не сработает автомат щита. Датчик тока для роли `aeration` рекомендуется BOM, но не блокирует дефолт `on`.
- `NODE_CONFIG_SPEC.md` в PR реализации: убрать фразу «0 = отключено», описать поле и приоритет E-STOP. Копия `firmware/NODE_CONFIG_SPEC.md` обновляется вместе с каноном.
- Схема NodeConfig становится контрактным файлом. Пока её нет, паритет не обещать.

Новый Python-сервис не нужен. history-logger публикует конфиг как сейчас, отдельной логики failsafe в нём нет, кроме отказа пропустить невалидный JSON, если схема уже на ingress.

## Критерии приёмки

1. Фикстура канала без `failsafe_state` и в схеме, и в host-тесте прошивки даёт `off`.
2. Канал `PERISTALTIC_PUMP` с `failsafe_state=on` отвергается Laravel до MQTT и отвергается парсером прошивки. В брокер payload не уходит.
3. На `storage_irrigation_node` или `relay_node` стенда: обрыв MQTT дольше таймаута гасит канал `off` и оставляет канал `on` включённым. Событие `link_loss_failsafe` называет оба канала.
4. Перезагрузка с `hold` поднимает выход в `off`. Перезагрузка с `on` включает выход до соединения с брокером.
5. Нажатый E-STOP гасит канал `on`. После отпускания выход сам не включается, пока не придёт команда или повторное применение политики загрузки — в соответствии с текущим контрактом E-STOP (снимок не восстанавливается).
6. `climate_node`: FAN с записанным `off` гаснет при обрыве; FAN с `on` при флаге охлаждения — нет. PWM без поля уходит в duty 0.
7. Спецификация NodeConfig больше не говорит, что `link_loss_timeout_sec=0` выключает таймер.
