# Аудит фронтенда, планировщика и настроек AE3

**Дата:** 2026-11-02. **Статус:** implementation report; поведение определяется кодом.

Compatible-With: Protocol 2.0, Backend >=3.0, Python >=3.0, Database >=3.0, Frontend >=3.0.

## Границы и выводы

Изучены страницы Settings и Zones, scheduler workspace и executions API, редактирование
authority documents, каталог `system.runtime`, PID schema и контракт AE3.
Сохранение настроек не запускает оборудование. Поток команд остаётся
Laravel scheduler → AE3 → History Logger → MQTT. API, миграции, типы задач и сервисы не меняются.

Обнаружены повторные редакторы PID, повторные загрузки scheduler workspace при смене зоны,
риск применения запоздавших ответов другой зоны и сохранение всего каталога runtime вместо
изменённых полей. Неиспользуемые компоненты и их старые тесты затрудняли поиск рабочего UI.

## Планировщик

- Представления «Обзор», «Расписания», «История» разделяют наблюдение и редактирование.
- Обзор показывает текущую задачу, три ближайших запуска и последние пять исполнений.
  Счётчик окон учитывает весь выбранный горизонт, а не размер краткого списка.
- История фильтруется по статусу и поиску; навигация клавишами работает по видимым строкам.
- В ручных расписаниях есть поиск и фильтры активности. Фоновое обновление не демонтирует
  таблицу, открытый редактор и сфокусированные элементы.
- Один composable владеет загрузкой, polling и подпиской на смену режима. Запоздавшие
  ответы другой зоны, старого выбора и закрытой панели игнорируются.
- Детали загружаются по выбору пользователя. Ошибка деталей отделена от ошибки workspace.
  Инженерная диагностика загружается при раскрытии блока.
- Вместо постоянной надписи Live показано время фактического обновления. `due_at`,
  `expires_at` и timeout не выдаются за прогноз завершения задачи.
- На узком экране колонки складываются, детали располагаются под основным содержимым.
  Горячие клавиши не перехватывают Enter в кнопках, полях и диалогах.

## Настройки

Глобальный каталог открывается через **Настройки → Параметры движка**. Он содержит
настройки Laravel scheduler/bridge и доступные параметры интеграции AE3. Он не является
универсальным редактором переменных окружения Python worker; startup-параметры worker
по-прежнему применяются согласно его lifecycle.

- Группы, поиск, технические поля и фильтры несохранённых/сохранённых настроек доступны
  в одном редакторе. Сохранённый override отличается от несохранённой правки.
- Черновик сравнивается с загруженными effective values. PUT содержит только изменённые
  ключи; неизменённые defaults не превращаются в overrides.
- Проверяются тип, целочисленность, диапазон и варианты выбора. Ошибки видны возле поля.
- Отмена доступна для одного поля и всего черновика. Ошибка сети сохраняет правки;
  обновление не затирает их. Переход со страницы и закрытие вкладки предупреждают о потере.
- Сброс требует существующего подтверждения; при ошибке диалог остаётся открытым.

В зоне **Автоматика → Настройки AE3** находятся профиль выполнения и его параметры.
Сводка профиля показывает воду, климат зоны, pH/EC воды и досветку простыми подписями.
Окно редактирования использует общий мастер автоматики; подтверждает потерю несохранённых
правок при закрытии или повторной загрузке и поясняет действие «Сохранить и применить».
**Коррекция раствора** разделена на готовность, датчики, насосы, процесс, PID,
историю PID и параметры коррекции. Форма загружается при первом открытии раздела;
переключение разделов коррекции сохраняет её черновик. Смена зоны очищает открытые формы.
В «Устройствах» оставлена ссылка на единый редактор коррекции/PID. Viewer видит PID
без возможности изменять поля, пресеты или отправлять сохранение.

Кнопка relay autotune удалена из зоны и launch: такого исполняемого контракта у AE3 нет.
Сохранённые исторические метаданные PID и backend endpoints этим рефакторингом не удаляются.
Валидация PID соответствует существующей `schemas/zone_pid.v1.json`.

## Удаление дублей и мёртвого кода

Удалены 28 runtime-файлов:

- Старые редакторы `AutomationEngine`, `AutomationProcessPanel`, `RelayAutotuneTrigger`,
  повторные `SchedulerStatCounters`.
- Неиспользуемые `Checkbox`, `ErrorState`, `GrowCycleCard`, `MiniTelemetryChart`,
  `NodeLifecycleTransition`, `PhaseProgress`, `SafeSvg`, `Sparkline`, `StatusPill`,
  `Toast`, `VirtualList`, `ZoneAIPredictionHint`, `ZoneHealthGauge`, `ZonesHeatmap`.
- Неиспользуемые `Shared/BaseWizard` (компонент, types, index), `Launch/Shell/index.ts`.
- Неиспользуемые composables `useAnimations`, `useApi`, `useFormValidation`,
  `useOptimisticUpdate`, `usePagination`, `usePerformance`.

Удалены 13 тестовых файлов исключительно для удалённых реализаций и устаревшие mocks.
Realtime-тест действующего `ZoneAutomationRuntimeSection` сохранён и переименован по
реальному предмету проверки. Общие метки планировщика и работа с черновиком PID вынесены
в утилиты; неиспользуемое построение старого timeline удалено из workspace composable.

Проверка использовала граф относительных и `@/` импортов, reexports и literal dynamic imports.
Корнями считались **все** Inertia Pages, app/bootstrap/SSR — консервативно, включая страницы,
которые пока не подключены к production routes. Проверены glob страниц и глобальные
регистрации в app.js; автоматической регистрации удалённых компонентов нет. После очистки:
539 runtime-модулей, 537 достижимы от корней; недостижимых Components/composables/utils нет.
Это результат аудита, не доказательство отсутствия любого семантически мёртвого кода.

## Проверки

- Полный Vitest с coverage: 251 файл, 1762 passed, 1 skipped на момент основного прогона.
  Statements 59.45%, branches 50.81%, functions 56.89%, lines 60.73%; пороги CI сохранены.
- Дополнительные регрессии покрывают частичный PUT, ошибки сохранения, гонки запросов,
  закрытие деталей, счётчик горизонта, фильтры, lazy loading, роль viewer и валидацию PID.
- Typecheck, production build, ESLint, API boundary и authority cleanup guard.
- Playwright: реальные Laravel/session/API для runtime-редактора; lifecycle и фильтры
  планировщика проверяются с детерминированными ответами executions/workspace.
  Локальный стенд использует testing PostgreSQL без Timescale и PHP 8.5;
  канонический PHP 8.2/Timescale прогон выполняется workflow CI.

Проверки интерфейса не заменяют испытания дозирования на физическом оборудовании.
